01 / THE ROUTINE

Survey first.
Then decide.

Set up a host and target folder, check what is there, and preview supported changes before running them. The CLI keeps the repository selection visible.

01

Prepare

init and doctor help configure a host, local folder, and credentials.

git_mirror doctor
02

Review

See branch and local change status across configured repositories.

git_mirror status --host github
03

Preview

Dry-run a supported maintenance command before changing checkouts.

git_mirror pull-all --host github --dry-run
02 / YOUR TOOLBELT

One folder.
Several useful passes.

READ

Know what needs attention

Combine repository status, uncommitted or unpushed work, and GitHub Actions conclusions.

status · local-changes · build-status
MAINTAIN

Keep checkouts moving

Clone account repositories, pull local copies, update branches from main, or prune stale local branches.

clone-all · pull-all · update-from-main · prune-all
FOCUS

Choose the right subset

Use repository names, tags, exclusions, and ignored status from your configuration to narrow a batch.

--only · --tag · --exclude

04 / THE SCOPE

For local checkouts
of GitHub repositories.

git-mirror works across a folder of local public GitHub or self-hosted GitHub Enterprise repositories. It does not synchronize two remote hosting services or run arbitrary scripts across projects.
